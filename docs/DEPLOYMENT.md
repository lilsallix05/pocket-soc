# Connect a consenting site's sensors

Local software is tested separately from Linux deployment. Wazuh, Zeek and Suricata binaries are not installed or run in this delivery environment. The following is an operational procedure, not a claim that a site's telemetry works.

1. Obtain scope/consent, choose the systems and capture interface, assign a technical owner and notification contact. Use a dedicated Linux sensor with reliable time synchronisation, an encrypted SSD, restricted administrator access and log retention agreed with the organisation. Size the Wazuh central components from its current quickstart; do not assume every mini PC can host an indexer, manager and packet sensor together. A small sensor can forward to an existing authorised Wazuh manager.
2. Install supported Wazuh components and Suricata or Zeek using the vendor's distribution instructions. Record package versions, NIC/capture point, `HOME_NET`, packet loss and timestamps. No install script is executed by this package. Refer to [Wazuh quickstart](https://documentation.wazuh.com/current/quickstart.html), [Wazuh IDS integration](https://documentation.wazuh.com/current/proof-of-concept-guide/integrate-network-ids-suricata.html), [Suricata EVE](https://docs.suricata.io/en/latest/output/eve/eve-json-output.html) and [Zeek logging](https://docs.zeek.org/en/lts/frameworks/logging.html).
3. Merge `ops/suricata-fragment.yaml` into the distribution config, retaining other required settings. Install `ops/pocket.rules` in its configured rule directory and validate with `suricata -T -c /etc/suricata/suricata.yaml`. The rule matches a harmless `/pocket-soc-test` HTTP marker; it is not a generic exfiltration signature. Use an owned test PCAP and `suricata -r <owned.pcap> -c <config> -l <empty-output-directory>` to verify output without network scanning.
4. For Zeek, append `ops/local.zeek` to site policy or run `zeek -r <owned.pcap> LogAscii::use_json=T` in an empty log directory. Confirm `conn.log` contains JSON objects. Adjust addresses/network assumptions in the detector for the site's topology before operational use. Default outbound classification requires a private/local source and a non-private destination; public-address internal networks need a site-specific change.
5. Merge Wazuh `localfile` sections from `ops/wazuh-agent-fragment.xml` into existing configuration. Resolve custom rule ID collisions before installing `ops/wazuh-local-rules.xml` on the manager. Confirm paths and read permissions, run `wazuh-logtest` with a representative EVE line, then inspect real manager `alerts.json`. Do not equate XML parsing with a passing Wazuh rules test.
6. Copy the app to `/opt/pocket-soc`. Create a dedicated `pocketsoc` account and `/var/lib/pocket-soc` owned by it. Grant read access to the log via the actual local log group/ACL. Adapt `ops/pocket-soc-collector.service`: its example group is `suricata`, which must exist on your distribution. Install the unit only after the paths, group and Python version are correct. The collector needs write access only to its database/checkpoint directory. A Wazuh-manager collector uses `--source wazuh --file /var/ossec/logs/alerts/alerts.json`; a Zeek collector uses `--source zeek --file /opt/zeek/logs/current/conn.log`. Give each stream a separate checkpoint.
7. Start the UI using the **same database**: `python3 soc.py --db /var/lib/pocket-soc/pocket-soc.sqlite serve --port 8765`. It binds only to `127.0.0.1`. Use an authorised SSH tunnel for a remote Linux host, not a public reverse proxy. This is a single trusted local-operator tool, without multi-user authentication.
8. Watch the collector's journal. Missing files, malformed lines and permission errors report `Collector unhealthy`; a bad complete line stops checkpoint advancement. Explicitly preserve/quarantine and resolve bad input. It reads only complete newline-terminated records, deduplicates canonical JSON by hash and restarts on truncation/inode rotation. It can miss unread tails from renamed files when log rotation races the poll; configure sufficient rotation retention and compare source counts. Current polling is every two seconds.
9. Run the harmless replay and measure separate UTC boundaries: packet replay start, sensor event emission, collector insertion, analyst acknowledgement. Save raw commands, timestamps, version strings, PCAP/log hashes and dropped-packet counts. The shipped microbenchmark measures only in-process normalization + threshold evaluation.
10. For 30 live days, collect daily counts, annotate true/false positives with a reviewer, assess lost telemetry and compare the same records under baseline/tuned policy. Do not count an unobserved day as zero. Preserve report exports and decisions outside the editable local database; backup via SQLite backup facilities while the service is live or copy it only after stopping services. Apply the organisation's retention and access rules.

Rollback: stop/disable the collector unit, preserve its database/checkpoints, restore backed-up sensor/Wazuh fragments, validate the restored configuration, then restart those services. The app has no automated containment or network-blocking actions.
